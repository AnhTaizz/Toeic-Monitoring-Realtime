BENCHMARK
.\scripts\verify-phase4-benchmark.ps1 -PostgresBin <PG_BIN> -JavaHome <JDK21_HOME> -MavenCommand <MAVEN_CMD>
python scripts/analyze-phase4-benchmark.py <RESULT_DIRECTORY>
- Opt-in JUnit test forks the packaged production Server JAR into a separate JVM and creates an owned PG schema.
- Same self-authored CC0 MOCK200 dataset for levels 1,2,5,10,20; three independent rooms per level.
- Generator creates candidates through the real API, creates the room, concurrently JOINs/prepares candidates,
  opens WS/heartbeats, STARTs, fetches the sealed exam, delivers three process events and three autosaves per candidate, drops WS, reconnects
  with unchanged writer/deadline, Submits and verifies SUBMITTED. Heartbeats continue every two seconds during the workload. A final acknowledged heartbeat
  and ONLINE precondition are required before each timed abort.
- Setup/import and five HTTP auth warm-ups are marked clients=0/round=0 and excluded from level statistics.
- Candidate setup and BCrypt room provisioning belong to the measured round; pooled HTTP latency includes
  provisioning, preparation and presence polling, so use raw operation labels for a narrower comparison.
- Audio/visual readiness is simulated from returned manifests. NO audio playback/full-media transfer or JavaFX
  workload is claimed by this benchmark. CPU/RAM Client metric means generator JVM, not desktop Client.
- All request/send/receive timestamps are taken with System.nanoTime in the same generator JVM.
  Event delivery ends when assigned Proctor WS receives matching event ID. No cross-machine wall-clock subtraction.
- Presence connect ends on proctor GET first ONLINE; disconnect ends on first non-ONLINE after WS abort.
  Detection includes polling/network/DB overhead; abort tests clean transport loss, not silent packet blackhole.
- CPU uses separate JVM ProcessHandle totalCpuDuration deltas over each round, excluding external PostgreSQL.
  100% means one logical core. RAM is Windows Get-Process WorkingSet64 sampled at round end, not peak/high-water RAM.
- Quantiles: nearest rank; p50/p95 pooled across the three repetitions at each level. Failures are retained as
  failed rows and counted in error rates; missing observations are not imputed as zeros.
- Closed/bounded workload with synchronized phases; not a sustained arrival-rate, multi-hour soak or capacity claim.
- Levels run in ascending order; transport warm-up does not imply a fully warmed JVM/BCrypt/media cache.
- One physical Windows host/loopback only. Background host workload is not controlled. No baseline/proposed claim.
- Public raw.csv/resources.csv/environment.json/summary.json contain no request/response bodies, tokens, PINs or
  passwords. Private server logs and runner XML are not distribution artifacts.
